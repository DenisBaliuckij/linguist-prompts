# linguist-prompts

*A public collection of prompts written and reviewed by linguists, organised per language and per subject. Every change goes through a pull request.*

Публичный репозиторий, в котором лингвисты совместно пишут, дорабатывают и обсуждают промпты. Промпты хранятся в Markdown-файлах, сгруппированных по языкам и по темам.

## Структура

```
languages/
  <язык>/
    <тема>/
      README.md    — о чём эта тема и как ею пользоваться
      prompts.md   — сами промпты
```

Пример: [`languages/russian/grammar/`](languages/russian/grammar/). Новый язык или новая тема — это просто новая папка, нигде ничего регистрировать не нужно.

## Как вносить изменения

Прямые коммиты в `main` запрещены. Любое изменение вносится через pull request и должно получить одно одобрение от другого участника. Подробности — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Еженедельная сводка

Каждое воскресенье в 18:00 UTC GitHub Actions собирает все pull request'ы, слитые за прошедшую неделю, и публикует сводку на русском языке — кто и что изменил — в виде Issue с меткой `digest` и заголовком «Сводка linguist-prompts: …». Если изменений не было, в Issue будет короткое сообщение «За неделю изменений нет». Все сводки собраны на вкладке Issues (фильтр по метке `digest`). Скрипт: [`scripts/weekly_digest.py`](scripts/weekly_digest.py).

### Как получать сводку на электронную почту

Письмо с новой сводкой рассылает сам GitHub. Есть два способа его получать:

- **Попасть в список получателей.** Мейнтейнер добавляет ваш логин GitHub в переменную репозитория `DIGEST_NOTIFY` (Settings → Secrets and variables → Actions → Variables; логины через пробел, запятую или точку с запятой). Тогда сводка начинается со строки «Для: @ваш-логин», и GitHub уведомляет вас. Переменная необязательна: если она пуста, строки «Для:» в сводке нет и письмо получают только те, кто подписан на репозиторий.
- **Подписаться на репозиторий самостоятельно.** Нажмите Watch → «All Activity» либо Custom → Issues на странице репозитория.

В обоих случаях в [настройках уведомлений GitHub](https://github.com/settings/notifications) должна быть включена доставка на электронную почту.

Важно: репозиторий публичный, поэтому Issue со сводкой — включая логины из строки «Для:» — видно всем.

Очень большие недели сокращаются: сначала из сводки убираются списки файлов, а если и этого мало — показывается только начало списка pull request'ов, и в конце указано, что показаны не все изменения (остальные — среди слитых PR репозитория). Так сводка укладывается в ограничение GitHub на размер Issue.

> **Ограничение GitHub.** Если в публичном репозитории 60 дней нет активности, запланированные workflow отключаются автоматически, и сводки перестают появляться. Если это случилось, включите workflow заново на вкладке Actions. Запланированный запуск может опоздать, а если GitHub пропустит его совсем, сводка за ту неделю позже не опубликуется: следующая сводка охватит только свою неделю. Пропущенную сводку мейнтейнер может опубликовать вручную — запустите workflow на вкладке Actions с выключенным `dry_run`. Это сработает только до следующего воскресенья 18:00 UTC: окно сводки привязано к календарю, и после этого момента вручную будет опубликована уже сводка за следующую неделю. Ручной запуск в том же окне, за которое сводка уже опубликована по расписанию, создаст второй Issue.
